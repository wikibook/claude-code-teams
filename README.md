# 팀을 위한 클로드 코드 완벽 가이드: 예제 저장소

위키북스 『팀을 위한 클로드 코드 완벽 가이드』의 예제 저장소입니다. 본문에 수록된 설정
파일과 스크립트는 모두 이 저장소의 실제 파일입니다. 저장소는 장별 디렉터리로 구분되어 있고, 각 장 폴더는 **그 장을 완주한 시점의
스냅샷**입니다. 같은 프로젝트라도 장이 진행되며 파일이 늘어나므로, 실습은 반드시
해당 장의 폴더에서 시작해 주세요.

각 장 폴더의 `README.md`에 그 장에서 사용하는
파일과 실행 방법이 정리되어 있으니 실습 전에 먼저 읽어 보시기 바랍니다. 본문의 "사용자 입력" 블록은
각 장 폴더의 `prompts/`에 한 건씩 텍스트 파일로 모여 있습니다(파일명은 `장-순번_요지.txt`).

<br>

## 예제 프로젝트

| 프로젝트 | 사용 장 | 설명 |
|---|---|---|
| hello-todo | 2장 | 브라우저 할 일 목록 앱. 첫 실습용 최소 프로젝트 |
| moneylog | 3장 | 지출 가계부 웹앱. 워크플로 실습용(시작 상태에 실습용 버그 포함) |
| paylog | 4~6장 | 결제 서비스 모노레포. 컨텍스트 설계·확장 기능·도입 문서 실습용 |
| notihub | 7·8장, 13~17장 | 사내 알림 서비스 조직. 팀 표준·거버넌스·자동화 실습용 |
| minishop | 9~12장 | 주문·쿠폰·환불을 다루는 쇼핑몰 백엔드. 팀 공정 실습용 |

1장·17장은 본문 서술 중심의 장이라 예제 폴더가 없습니다. 15장 폴더에는 사용자 입력만 있습니다.

<br>

## 장별 폴더

- `02장 클로드 코드 시작하기`: hello-todo. index.html을 열어 실행, `node --test`
- `03장 핵심 개발 워크플로`: moneylog. `python run.py` 후 localhost:8000, `python -m pytest tests/`
- `04장 CLAUDE.md와 컨텍스트 설계`: paylog(시작 상태, 의도적으로 지침과 README 없음) + paylog-complete(지침 정답 모음)
- `05장 팀 인프라를 만드는 확장 기능`: paylog(커맨드·훅·서브에이전트·스킬·MCP 완주 스냅샷)
- `06장 도입 전략 수립`: paylog(파일럿 기준·보안 검토 답변 문서 양식)
- `07장 팀 공통 환경 구축`: notihub(팀 CLAUDE.md, 권한·훅 설정, 정책 문서)
- `08장 노하우의 조직 자산화`: notihub(스킬·온보딩 문서) + claude-plugins(사내 마켓플레이스와 플러그인)
- `09장 작업 결합의 공학`: minishop(계약 문서·계약 테스트·게이트, 결합 실패 재현)
- `10장 Git 전략과 병렬 작업`: minishop(워크트리 준비 스크립트와 견본)
- `11장 코드 리뷰 파이프라인`: minishop(리뷰 워크플로, 리뷰어 서브에이전트 3종)
- `12장 품질·테스트·평가 표준`: minishop(문서 동기화 훅, 평가 세트와 러너)
- `13장 비용 거버넌스`: notihub(주간 비용 리포트 스크립트, 지출 데이터 샘플)
- `14장 보안과 사고 대응`: notihub(규제 프로파일·샌드박스 설정, 관리 설정 드롭인)
- `15장 에이전트 팀과 멀티에이전트`: 사용자 입력만(에이전트 팀 조사 지시)
- `16장 파이프라인 통합과 헤드리스 자동화`: notihub(헤드리스 스크립트, GitHub Actions 워크플로, 템플릿 이관 배치)

## 실습 준비

- 클로드 코드 최신 버전이 필요합니다. 설치와 인증은 책의 부록 A를 따라 주세요.
- Python 3.11 이상, Node.js 22 이상을 사용합니다. 일부 예제는 jq, gh CLI가 추가로 필요합니다.
- 셸 스크립트는 POSIX 셸(sh) 기준입니다. Windows에서는 Git Bash 또는 WSL을 사용하고,
  PowerShell에서의 실행 방법은 부록 A를 참고해 주세요.
- 11장과 16장의 GitHub Actions 실습에는 본인 소유의 시험용 저장소가 필요합니다.
  절차는 각 장 폴더의 README.md에 있습니다.

<br>

## 유의점

- 4장의 paylog에 CLAUDE.md와 README.md가 없는 것은 의도된 시작 상태입니다(/init 실습 전제).
- 3장 moneylog의 버그와 9장의 결합 실패 재현 코드는 실습 재료이므로 수정된 상태가 아닙니다.
- 훅이 포함된 폴더에서는 정책상 차단되는 동작(.env 수정 등)이 있으며, 이는 정상입니다.
