# 팀 실행 예외 신청서

에이전트 팀(멀티에이전트) 실행은 단일 세션보다 토큰 비용이 몇 배로 늘어난다.
사람의 감독 시간이 추가되고 조율 실패의 위험도 커진다. 따라서 팀 실행은 표준
사용이 아니라 **사유와 기간을 남기는 예외**로 시작한다. 손익이 검증된 작업
유형부터 표준으로 전환한다(본문 15.2.1, 13.3.1). 이 양식은 그 손익 계산을 절차로
고정한 것이다.

## 판단의 기준: 손익 부등식

팀 실행이 정당화되는 조건은 다음 부등식 하나로 정리된다.

> 시간 가치 + 품질 이득 > 토큰 비용 + 조율 실패 비용 + 검토 비용 + 감독 비용

좌변을 채울 때 흔히 저지르는 과대평가가 두 가지 있다. 첫째, **시간 가치는 줄인
시간의 길이가 아니다.** 장애 조사처럼 지연이 곧 손실인 작업은 한 시간의 값이 크다.
마감에 여유가 있는 백로그 작업은 같은 한 시간을 줄여도 값이 작다. 둘째, **품질
이득은 기존 공정에 추가되는 발견만 계산한다.** 게이트(9장)와 단일 리뷰어(11장)가
이미 발견했을 결함은 팀의 이득으로 계산하지 않는다. 우변에서는 **감독 시간을
빠뜨리기 쉽다.** 팀이 세 시간에 작업을 완료했더라도 사람이 그 세 시간 동안
감독했다면 절약된 시간을 전부 이득으로 볼 수 없다.

## 신청서

**작성일**: YYYY-MM-DD  **신청자**:   **승인자**:   **유효 기간**: (예: 이번 스프린트)

### 1. 작업과 분해 계획

| 항목 | 내용 |
|---|---|
| 대상 작업 | |
| 태스크 목록(건수) | |
| 팀원별 파일 소유 분할 | |
| 팀원 간 통신이 필요한 이유 | |

마지막 행이 비어 있으면 팀 실행이 아니라 서브에이전트나 병렬 세션이 적합하다.
결과만 취합하면 되는 작업은 팀원 간 통신이 필요하지 않다.

### 2. 예상 시간 이득과 그 가치

| 항목 | 내용 |
|---|---|
| 단일 세션 기준 예상 소요 | |
| 팀 실행 기준 예상 소요 | |
| 단축되는 시간 | |
| 그 단축이 만드는 가치 | |

"가치" 칸에는 시간이 아니라 결과를 적는다. 출시 일정 확보, 장애 지속 시간 단축,
의존 팀의 대기 해소처럼 조직이 실제로 얻는 것이어야 한다.

### 3. 예상 토큰 비용과 팀원 구성

| 항목 | 내용 |
|---|---|
| 리드 모델 등급 / 수 | |
| 팀원 모델 등급 / 수 | |
| 단일 세션 대비 예상 비용 배수 | |
| 예산 상한(토큰 또는 금액) | |

리드에는 상위 등급, 배분된 작업을 수행하는 팀원에는 균형 등급을 두는 것이
기본 배정이다(표 13.5). 작업을 마친 팀원은 즉시 종료한다.

### 4. 조율 위험에 대한 평가

| 항목 | 내용 |
|---|---|
| 파일 충돌 가능성(공유 파일 유무) | |
| 의존 대기 가능성(태스크 간 순서 의존) | |
| 대응 방법 | |
| 감독 담당자와 예상 감독 시간 | |

### 5. 판정

- [ ] 팀원 간 통신이 결과의 품질을 실제로 높이는 작업이다
- [ ] 파일 소유권을 분리할 수 있다
- [ ] 병렬 실행의 이득 합이 추가 비용을 충분히 넘어선다(부등식 성립)

세 조건 가운데 하나라도 충족되지 않으면 승인하지 않고 더 저렴한 대안을 지정한다.
순차 의존이 강하면 계획을 충분히 갖춘 단일 세션, 결과만 필요하면 서브에이전트,
독립 작업이면 병렬 세션이 대안이다(그림 15.2).

### 6. 실행 후 실측 기록 (회고 시 작성)

| 항목 | 예상 | 실측 |
|---|---|---|
| 소요 시간 | | |
| 토큰 비용(배수) | | |
| 감독 시간 | | |
| 기존 공정이 놓쳤을 발견의 수 | | |
| 조율 실패(충돌·대기) 발생 | | |

실측이 예상보다 나쁜 항목이 있으면 그 원인을 한 줄로 남긴다. 같은 작업 유형의
신청이 세 차례 이상 손익을 충족하면 예외가 아닌 표준 사용으로 전환을 검토한다.

## 작성 예 (본문 notihub 사례)

| 항목 | 작성 예 |
|---|---|
| 작업과 분해 계획 | 알림 채널 추가. 태스크 12건, 팀원 3명, 채널별 디렉터리 분담. 채널 간 공통 인터페이스 합의가 필요해 통신이 필요함 |
| 예상 시간 이득과 가치 | 이틀 단축. 출시 일정의 여유 확보 |
| 예상 토큰 비용과 구성 | 리드 상위 1, 팀원 균형 3. 단일 세션 대비 약 5배 |
| 조율 위험 평가 | 파일 소유 분리 완료, 공유 파일 없음. 감독 담당 1인, 착수·통합 시점에 각 30분 |

반대 방향의 사례도 있다. notihub의 중복 발송 버그는 단일 세션으로 사흘 동안
원인을 찾지 못했다. 네 가지 독립 가설(스케줄러 경합, 캐시 불일치, 시간대 처리,
발송 API 응답 순서)을 팀으로 병렬 검증하자 반나절 만에 원인이 좁혀졌다. 한 팀원의
발견이 다른 가설을 반박한 결과다. 이 사례는 시간 가치가 큰 장애 조사에서 팀원 간
통신이 품질을 높인 경우이자, 부등식이 성립하는 전형적인 예다.
