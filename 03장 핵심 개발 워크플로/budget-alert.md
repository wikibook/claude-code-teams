# 예산 경고

## 목표
카테고리별 월 예산을 설정하고, 그 달의 지출이 예산을 넘으면 화면에서 경고를
보여준다.

## 범위 밖
- 예산의 다음 달 이월, 알림(메일·푸시) 발송, 예산 변경 이력
- 월별로 다른 예산. 예산은 월과 무관한 전역 설정이다(아래 "예산의 시점" 참고)
- 80% 근접 같은 단계별 경고. 초과했을 때만 경고한다

## 데이터
- data/budgets.json에 저장한다. 형식: {"식비": 300000, "교통": 100000}
- expenses.json은 변경하지 않는다.
- 파일이 없으면 예산이 하나도 설정되지 않은 것으로 보고 {}처럼 다룬다.
  첫 실행에서 조용히 통과해야 한다.
- 파일이 있는데 JSON 파싱에 실패하면 500을 돌려준다. 조용히 {}로 덮어써서
  사용자가 설정한 예산을 날리지 않는다.

### 예산의 시점
budgets.json에 월 키를 두지 않는다. 어느 달을 조회하든 현재 저장된 예산
하나로 판정한다. 즉 예산을 올리면 과거 월의 경고도 같이 바뀐다. 이는 의도된
단순화이며, 월별 예산이 필요해지면 그때 형식을 확장한다.

## 인터페이스

### GET /api/budgets
- 200, {"식비": 300000, "교통": 100000}
- 설정된 예산이 없으면 200과 {}

### PUT /api/budgets
본문의 카테고리만 갱신하는 **부분 병합**이다. 본문에 없는 카테고리의 예산은
그대로 남는다.

- 본문 {"카테고리": 금액}, 성공 200. 응답 본문은 병합 후의 예산 전체
- 금액이 null이면 그 카테고리의 예산을 **해제**한다(budgets.json에서 키 제거)
- 금액은 **0 이상의 정수**여야 한다. 0은 "이 카테고리엔 한 푼도 쓰지 않는다"는
  유효한 예산이며, 1원이라도 쓰면 초과다. 삭제는 null이 담당하므로 0과 의미가
  겹치지 않는다
- 카테고리는 models.CATEGORIES 안에 있어야 한다
- 유효하지 않으면 400과 {"errors": [...]}

**원자성**: 본문에 여러 카테고리가 오고 그중 하나라도 유효하지 않으면 전체를
거부한다. 400을 돌려주고 budgets.json은 전혀 건드리지 않는다. 부분 저장된
중간 상태가 생기지 않는다.

```
저장됨: {식비: 300000, 교통: 100000}

PUT {"식비": 350000}          → 200, {식비: 350000, 교통: 100000}
PUT {"교통": null}            → 200, {식비: 350000}
PUT {"식비": 300000, "교통": -5} → 400, 식비도 저장되지 않음
```

### GET /api/summary?month=YYYY-MM
응답에 "alerts" 배열을 추가한다. 기존 total, by_category 필드는 그대로다.

- 초과 항목: {"category": "식비", "budget": 300000, "spent": 321000,
  "over": 21000}
- 초과가 없으면 빈 배열
- 정렬은 **over가 큰 순서**다. 가장 문제가 큰 카테고리가 먼저 온다

### services/budget.py
- get_budgets(path)
- set_budgets(path, changes) — 부분 병합. null 값은 삭제
- over_budget(expenses, budgets, month)

파일 입출력은 budget.py 안에서 직접 처리하고 경로만 주입받는다. 기존
Storage 클래스는 expenses.json 전용으로 남겨 두어 지금 통과 중인 테스트에
영향을 주지 않는다. JSON 읽기/쓰기가 storage.py와 budget.py 두 곳에 생기는
중복은 감수한다.

## 판정 규칙
- 초과 판정은 환불을 차감한 **순지출** 기준이다. summary.monthly_total과
  category_totals가 이미 부호를 살려 합산하므로 그 값을 그대로 쓴다
- 예산이 설정되지 않은 카테고리는 경고하지 않는다
- **spent > budget일 때만 초과**다. 정확히 같으면(예산 50,000 / 지출 50,000)
  예산을 지킨 것으로 보고 경고하지 않는다. over가 0인 경고는 생기지 않는다
- 환불이 지출보다 커서 순지출이 음수인 카테고리는 당연히 초과가 아니다

## 화면

### 경고 표시
요약 카드(파란 카드) 안에서 처리한다. 카드 밖에 별도 배너를 두지 않는다.

- 초과한 카테고리의 칩을 빨간 계열로 바꾼다
- 카드 하단에 초과 요약을 한 줄씩 넣는다: "⚠ 교통 5,000원 초과"

```
┌─ 요약 카드 ──────────────────┐
│ 이번 달 지출                  │
│ 643,000원                     │
│ [식비 73,000] [🔴교통 55,000] │
│ ⚠ 교통 5,000원 초과           │
└───────────────────────────────┘
```

### 예산 설정
요약 카드 아래에 **접어둔** "예산 설정" 섹션을 둔다. 펼치면 5개 카테고리의
입력칸과 저장 버튼이 나온다. 평소에는 화면을 차지하지 않는다.

- 빈 입력칸 = 예산 없음. 저장 시 해당 카테고리를 null로 보내 해제한다
- 저장에 성공하면 요약과 목록을 다시 그린다

### 데이터 로딩
app.js의 기존 Promise.all에 GET /api/budgets를 하나 더 추가한다. summary
응답에 예산을 끼워 넣지 않는다 — summary는 월별 집계, budgets는 전역 설정으로
엔드포인트 책임을 나눈 채로 둔다.

### 손대지 않는 것
예산은 설정했지만 그 달 지출이 0인 카테고리는 칩이 나오지 않는다(app.js가
지출이 있는 카테고리만 그리기 때문). 그대로 둔다. 요약 카드는 "쓴 돈"을
보여주는 곳이고, 경고 대상도 아니므로 기능상 누락이 없다.

## 검증
1. python -m pytest tests/ 전체 통과 (budget 테스트 포함)
2. 브라우저에서 식비 예산을 30000으로 설정하고 2026-07 조회 시 식비 경고가
   보일 것
3. 예산 미설정 카테고리(기타)는 경고가 없을 것
4. 예산을 지출과 같은 값으로 맞추면 경고가 사라질 것
5. PUT에 잘못된 값을 섞어 보내면 400이 오고, 같이 보낸 정상 값도 저장되지
   않을 것
6. 환불이 포함된 카테고리는 순지출 기준으로 판정될 것 (환불로 예산 아래로
   내려가면 경고가 사라진다)
